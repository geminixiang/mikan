獨立的記憶整理工作，透過 Office maintenance barrier 讀取 session 證據，更新 MEMORY.md；不由 /new 隱式觸發。

交出去的是工作，不是對話關係。

beta.61 自動 handoff 先限頂層 Slack DM。一般簡短問題仍直接回答，既有任務 thread 不再遞迴 handoff。

主 DM 理解請求

模型選擇直接回答，或單獨呼叫 start_task。混合 handoff 與其他工具的同批呼叫會被阻擋。

Slack 建立確認訊息與 task thread

記錄 task root，建立獨立 scoped session，交付完整任務文字與附件引用。它不自動继承主對話全部工具歷史。

主對話結束本輪，任務獨立執行

Task 使用自己的 queue、runner 與 v4 session；主 DM 可接下一則問題，不等待 task 完成。

同一任務可觀察、引導與停止

常見純進度問句直接查 runtime／v4。其他自由問法可用 task_status。文字補充由 steering 送到下一個工具批次邊界；stop 走優先取消。

交付結果，再通知請求人

結果留在 thread，符合通知條件時新增原生 mention。停止通知也留在輸入 thread；停止後明確續作是同 session 的新 operation。

Thread 是平台位置；task 是用途；session 是歷史與執行身分。圖中文字是互動示意，不保證模型逐字照說。

進度不改任務

純狀態 shortcut 不跑模型、不送 steering。多個 active task 時不猜；歷史查詢限制十筆，但保留所有 active task。

取消不是回滾

記錄 control input 處置，避免取消後被 history sync 加回。Abort 需等待合作式收尾，無法撤銷已完成的外部操作。

目前限制

未提供自動 crash recovery、完整主 DM 自然語言取消定位。Steering 限當前 actor 的文字；新附件需停止後續作。

Session 是容器，lane 是工作線。

Pi v4 原生支援 multi-lane，但目前 mikan 採用「每個平台 session key 對應一份 session 檔，使用 main lane」。

Multi-lane ≠ 多個 sandbox。
同一 session 多 lane 可以獨立執行，但共用 harness 的部分配置與生命週期。採用前需整理 mikan 的 actor 綁定、事件路由、writer 管理與 Session View。
層級 Pi v4 已有 mikan 負責
Session / branch 歷史樹、transaction、values、branch tips Office 路徑、writer ownership、平台歷史同步
Lane 模型配置、啟用工具、持久 inbox 目前固定 main；平台 session key 決定 runner 身分
Operation accept / drive / steer / abort / resume、terminal result 授權、預算、準備與 settlement、控制入口
Recovery 重開可辨認未結束 operation；safe replay 與未知結果 啟動／恢復政策與使用者回饋；目前不自動恢復任務
Delivery operation completed 不證明外部訊息送達 Responder 最終發送、錯誤上報、requester mention

Fork 複製選定歷史，不複製正在執行的 operation／pending queue。已完成取消後的「繼續」是新 prompt；crash recovery 的 resume 是另一種操作。
