Executive summary

目前是一個 conversation-scoped agent extension system

8

Agent lifecycle hooks

可改寫 prompt、攔截工具、處理結果，以及觀察 turn、compaction、error 與 budget。

3

Contribution points

可註冊 agent tool、deterministic chat command，以及 bundled skill。

1× conversation

Activation scope

每個 conversation/session runner 建立時重新載入並 activate；目前沒有 application singleton。

Host process

Trust model

Extension 擁有 host 權限，不在 agent sandbox 中執行，因此安裝必須是管理員操作。

Event file

Schedule transport

現有 schedule 會寫入 event file，最後啟動 autonomous agent run，不是直接執行 handler。

Text first

Platform effects

目前可 notify、react、upload；notify 只接收文字且不回傳 message receipt。

核心判斷：現有系統很適合 prompt policy、tool augmentation、audit/redaction 和 conversation-local state；但缺少跨 conversation singleton、deterministic background execution、isolated subagent operation，以及可追蹤的 rich messaging。

Intervention timeline

Extension 在什麼階段可以介入

01
Module import
Entrypoint 被 jiti import；top-level code 已執行，但安裝驗證不會呼叫 activate。Module 本身位於 host-only state dir。
02
Activation
activate(api) 每個 conversation runner 呼叫一次，可註冊 hook、tool、command、disposer，並建立 conversation/shared state。
03
Command dispatch
Built-in slash command 未命中後，ExtensionRegistry 可執行 registerCommand handler；不呼叫模型，也不寫入 agent session。
04
Before model
before_agent_start 可改寫 system prompt/user prompt 或阻擋整個 turn；blocked turn 不會進 transcript。
05
Before tool
tool_call 可依 tool name、args、origin 決定是否阻擋；v1 語意為 first non-undefined wins。
06
After tool
tool_result 可串接改寫 tool content 與 error flag，適合 redaction、truncation、policy normalization。
07
During agent output
message_end 在每則 agent message 完成後收到事件；turn_end 在整個 turn settled 後收到新增訊息。
08
Recovery/control
session_compact、agent_error、budget_exceeded 可觀察 compaction、terminal error 與 budget circuit breaker。
09
Out-of-band effects
Extension 可在任何 handler 中呼叫 notify、react、uploadFile 或 triggerRun。
10
Disposal
onDispose 與 activate 回傳的 disposer 以 LIFO 執行；錯誤會被記錄但不向外傳播。
Current API inventory

現有 Extension API 能處理什麼

api.on()

註冊 agent lifecycle hooks，取得 interactive/event origin。

  • Prompt policy
  • Tool guardrail
  • Result redaction
  • Turn/error observability

registerTool()

把新的 typed AgentTool 加入該 conversation 的 agent tool set。

  • Domain CRUD
  • External API action
  • Host-side computation

registerCommand()

處理 deterministic /name args chat command，不啟動 agent。

  • 快速查詢
  • 設定切換
  • 管理操作

api.context

提供 conversation ID、workspace dir、目前 model 與 thinking level。

  • Conversation routing
  • Model-aware policy
  • Workspace-aware integration

api.paths

取得 host-only data directory；平台只提供路徑，不管理 schema。

  • dataDir：conversation private
  • sharedDataDir：cross-conversation

api.secrets

依 extension slug 讀取管理員 provision 的 secret；Extension 無法寫入。

  • get(key)
  • list() 只列名稱

api.schedules

管理 periodic / one-shot agent-run schedule，持久化為 event file。

  • upsert
  • delete
  • list
  • cron + timezone

notify / react / uploadFile

透過 embedder 提供的平台 bot 直接產生 side effect。

  • Text notification
  • Emoji reaction
  • Host file upload

api.subagent.run() NEW

啟動 fresh、isolated、non-recursive subagent；同一個 core runner 也提供一般主 agent 的內建 subagent tool。

  • Explicit tool allowlist；預設無 tools
  • Turn/token/cost/duration budget
  • Optional TypeBox structured output
  • Run ID、status、usage metadata
  • 主 agent tool 支援 bounded DAG：8 nodes / 16 edges / depth 4 / concurrency 4
  • Node progress 透過 tool_execution_update → replaceResponse 同步到三個平台

triggerRun()

建立 immediate event file，盡快啟動不繼承 conversation history 的 autonomous agent run。

  • Self-contained task text
  • 由 model 決定後續行為

api.log()

寫入帶有 extension name prefix 的 mikan structured log surface。

  • 目前只接受文字
  • 沒有 extension span/metric API

onDispose()

註冊 runner 被丟棄時的 cleanup；多個 disposer 反向執行。

  • 關閉 DB
  • 移除 listener
  • 釋放 host resource

skills/

Extension 可附帶 SKILL.md；內容會 inline 進 prompt，因為 extension dir 不掛入 sandbox。

  • Extension-specific guidance
  • 隨 package 安裝
Scope & trust

Conversation scope、共享資料與安全邊界

Global code ≠ singleton instance

安裝於 global/extensions 代表所有 conversations 都會載入，但每個 runner 仍各自 activate 一次。

Conversation data

dataDir 位於該 conversation 下，刪除 conversation 時一起消失，是預設安全選擇。

Shared data

sharedDataDir 是顯式 cross-conversation opt-in；tenant partition 與 concurrency 由 extension 負責。

Host-only execution

Extension 直接在 mikan process 執行，可使用 Node filesystem/network/process 能力，不受 agent sandbox 限制。

Optional host services

Schedule、message、reaction、upload、secret resolver 由 embedder 注入；缺少時 API 會丟出 informative error。

Cooperative schedule ownership

Schedule filename prefix 用於辨識 ownership，但 events directory 對同一 workspace trust domain 內的 agent 可寫。

⚠
Extension 不是 sandbox。 Module import 與 activate 都發生在 host process；extension 可接觸 host filesystem，並可能透過注入服務使用 platform token 與 vault secret，因此只能從 host-controlled state directory 載入經審核的程式碼。
Phase 1 additions

第一階段要新增的六項能力

以下全部用紅色標示；api.subagent.run 已在目前 working tree 實作，其餘仍是第一階段提案。

Phase-one addition

1. activateApplication

讓 extension installation 在整個 mikan runtime 中只 activate 一次，安全承載跨 conversation 的 shared state、event subscription 與 task registration。

  • 與現有 conversation activate 並存
  • 明確 startup/shutdown ownership
  • 避免 global extension 重複註冊背景工作
export async function activateApplication(api) {
  // once per installed application
  return () => closeResources();
}

2. api.tasks

註冊不經 agent/model 決策的 deterministic background handler，具 schedule、retry、timeout、concurrency 與 run history。

  • 與 agentic api.schedules 分離
  • at-least-once，不宣稱 exactly-once
  • 支援 cron、manual run、pause、rerun
api.tasks.register({
  name: "daily-report",
  trigger: { cron: "0 9 * * *", timezone: "Asia/Taipei" },
  retry: { attempts: 3 },
  concurrency: "skip",
  handler: async ({ runId, signal }) => { /* deterministic */ },
});

3. api.subagent.run IMPLEMENTED

以通用 SubagentRunner 啟動 fresh isolated subagent，同時支援主 agent 的 subagent tool（平行 tasks[]）與 extension api.subagent.run。

  • 預設無 conversation history、無 tools
  • 支援 explicit tools、budget、cancel 與 TypeBox output schema
  • 回傳 run ID、status、model/token/cost/duration metadata
const result = await api.subagent.run({
  task: "Classify this project update",
  input,
  tools: [],
  outputSchema: ResultSchema,
  budget: { maxTurns: 1, maxCostUsd: 0.05 },
});

4. api.messages

把現有 notify 深化成可發送、更新、thread reply、DM 並回傳 message receipt 的跨平台 message interface。

  • 保留 text fallback
  • 支援 stable destination address
  • receipt 可供 audit 與 retry 判斷
const receipt = await api.messages.send({
  to: { conversationId, platform },
  threadId,
  content: { text },
  idempotencyKey,
});

5. Capability negotiation

讓 extension 查詢 platform/embedder 是否支援 history、directory、actions 或 rich messages，不把 Slack-specific surface 強塞給所有平台。

  • Optional、versioned capabilities
  • Runtime feature detection
  • 支援 graceful degradation
const history = api.capabilities.get("messages.history.v1");
if (history) {
  for await (const message of history.list(query)) { /* ... */ }
}

6. Permission declaration

讓 extension 在安裝或 activation 前宣告需要的敏感能力，由管理員審核 message access、model usage、background execution 與 secrets。

  • Manifest-time review
  • Capability 與 permission 對應
  • 缺少權限時明確拒絕，不默默降級
{
  "mikan": {
    "permissions": ["tasks", "model", "messages:send"]
  }
}
