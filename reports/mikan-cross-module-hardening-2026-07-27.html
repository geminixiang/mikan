所有主要改動

附件路徑與上傳改為 fail-closed

模型輸入只能解析至 runtime workspace 內；禁止 ..、host absolute path、越界與 symlink component。真正讀檔改由 active Executor.readFileBase64NoSymlinks capability 負責；缺能力即拒絕，不再把 runtime path 當 host path。

私密 staging

附件內容先寫入 workspace 外的 0700 暫存目錄與 0600 檔案，再交給平台 uploader，最後無論成功或失敗都清除。

Host no-symlink transport

Linux host executor 逐 path component 使用 no-follow descriptor 語意；不支援的平台安全拒絕，而非降級為可競態的 pathname。

Runtime cache generation

新增 global 與 per-conversation runner generation。runner 建構跨越設定變更時，舊 runner 會 dispose 並重新建立，不會被註冊到 session cache。

Busy conversation 延遲失效

global LLM 設定寫入後，busy conversation 標記 pending clear；等同 conversation 所有 session settlements 完成後再清除 cached runners。

Session Dream lifecycle 統一

直接與自動 Dream 都納入 runSettlement、in-flight、busy 判斷、清理與 idle eviction，避免執行中被 dispose。

正常 run settlement eviction

將 idle/max-session eviction 移至清除 runSettlement 之後，避免正常流量長期保留無上限 runner。

Session watermark 自動恢復

若 log.jsonl 截斷或重建後找不到舊 watermark，改為重播 bounded history，並沿用 represented-message 去重，不再永久停止同步。

Thread／rotation 測試加強

新增 automatic rotation、thread startup、Dream gate、global refresh 與 session reset 的競態回歸測試。

Conversation pending clear

SessionLifecycle 新增 conversation pending clear，只有在所有相關 session 都沒有 running/settlement 時才一次 discard。

/model 參數契約修復

/model foo、空 model、多餘參數與未知 thinking suffix 會明確拒絕，不再誤顯示「目前模型」。

Colon model ID 相容

先查完整自訂 model ID，例如 provider/model:2026-01；只有完整 ID 不存在時才把末尾解析成 thinking shorthand。

Registry 單一來源

runtime runner 與 default ModelCommandHandler 共用同一 MikanModels instance，避免驗證與實際執行模型目錄漂移。

Vault key traversal 防護

所有 vault read/write/copy target 入口共用 safe-segment validator，拒絕 absolute path、.、..、slash、backslash 與 control characters。

Sandbox path containment

RuntimePathContext 以 canonical lexical containment 驗證 runtime 與 host root，避免 sibling-prefix 或 parent traversal 被翻譯成 workspace 外路徑。

Optional capability 明文化

Executor 新增 no-symlink read capability；介面要求不具安全能力的 adapter 省略或 fail-closed。

Package ref checkout 隔離

同 repo 不同 ref 使用 ref-keyed checkout；同 ref 的不同 subpath 可共用。避免 v1/v2 互相 reset working tree。

完成 marker 與 dependency retry

mikan-ref 只在 subpath 驗證與 dependency install 成功後寫入；失敗重試不會誤判為已 materialize。

Legacy checkout migration

markerless 舊 checkout 只有在 Git 能證明 clean HEAD 與指定 ref 一致時才允許 offline reuse；無法證明的 pinned ref 必須重新 fetch。

Git subpath containment

CLI extension install 拒絕 absolute／.. subpath，並以 realpath 確認 symlink 最終位置仍在 clone root 內。

One-shot event timestamp

builder 與 parser 共用 ISO 8601 validator，要求 Z 或 ±HH:MM；顯式驗證月份、日數、閏年、時間與 offset，拒絕 Feb 30 的 Date normalization。

多語文件同步

英文、日文、繁中、簡中 events 文件均說明 one-shot timestamp 必須帶 UTC offset。

安全影響

攻擊面 修復前風險 現在的保護
模型要求附加檔案 runtime path 可能被誤當 host path；symlink/TOCTOU 可讀取 workspace 外資料。 runtime lexical containment + executor atomic no-symlink capability + private staging；無安全能力即拒絕。
Vault key 未驗證 key 可能經 join 逃逸 vault directory。 所有入口使用相同 safe path-segment validator。
Extension git subpath #../../ 或 symlink 可令 npm install／copy 操作 checkout 外路徑。 parse-time traversal rejection、resolve containment、realpath containment。
Package refs 同 repo 不同 ref 共用 checkout，可能載入錯誤版本；失敗 install 仍被視為完成。 ref-keyed checkout、完成 marker、legacy evidence-based migration。
Runner settings busy 或建構中的 runner 可能永久保留舊 global/model 設定。 pending invalidation + settlement clear + generation retry。
Event scheduling 無 offset timestamp 依 host timezone 解讀；無效日期被正規化。 嚴格且共用的 ISO/calendar validator。
功能取捨：Attachment 安全能力目前採 fail-closed。若 executor 尚未實作 atomic no-symlink read，attachment／自動圖片上傳會拒絕，而不是用不安全 fallback。

結論

此次變更已把多個原本靠隱含共識維持的接口，轉為明確型別、fail-closed capability、集中 parser/validator、settlement-aware lifecycle、可遷移 persisted format，以及可執行的 contract tests。最重要的成果是：當 adapters、runtime、sandbox、vault 或 packages 任一方改變時，producer 與 consumer 現在有共同的文件與測試面可以同步驗證。

同時，重跑審核揭露的剩餘問題已在本報告中與已完成項目分離，避免將發現誤當成修復。
