## Prerequisites

- Node.js `>=22.19.0`
- at least one complete Slack, Telegram, Discord, or GitHub credential set
- a persistent state directory (default `~/.mikan`); the working directory defaults to `<state-dir>/workspace`
- Docker available to the PM2 user when using `image:*` or `container:*`

The published `mikan-sandbox` image is a tool runtime, not a standalone mikan server image. PM2 runs `mikan` on the host; image mode creates and manages containers through the host Docker daemon.

## PM2 deployment

<Steps>

1. Install mikan and PM2:

   ```bash
   npm i -g @geminixiang/mikan pm2
   ```

2. Create the global settings file in the exact state directory the service will use:

   ```bash
   mkdir -p /srv/mikan/workspace
   mikan onboard --state-dir=/srv/mikan/state
   ```

   Review `/srv/mikan/state/settings.json`. The directory must be owned by the PM2 process user and
   must not be world-writable; `chmod 0700 /srv/mikan/state` is recommended.

3. Create the secrets file. All platform tokens, provider keys, and other secrets live in
   `~/.mikan/mikan.env` — mode `0600`, outside any repo tree — and the ecosystem file loads it at
   start. Never put secrets in the ecosystem file or PM2's own environment:

   ```bash
   curl -o ~/.mikan/mikan.env https://raw.githubusercontent.com/geminixiang/mikan/main/deploy/pm2/mikan.env.example
   chmod 600 ~/.mikan/mikan.env
   ```

   Fill in at least one complete platform credential set plus an LLM provider key. Run `mikan env`
   to see the full annotated inventory and what is currently set.

4. Pull the managed sandbox image:

   ```bash
   docker pull ghcr.io/geminixiang/mikan-sandbox:latest
   ```

   Do not also start a long-lived container when the selected mode is `image:*`. A pre-existing
   container is needed only for `container:<name>` mode.

5. Download the ecosystem file:

   ```bash
   curl -O https://raw.githubusercontent.com/geminixiang/mikan/main/deploy/pm2/ecosystem.config.cjs
   ```

   The ecosystem file is supervision-only: process name, restart policy, graceful-shutdown timeout,
   and the `mikan.env` loader. Behavior (model, sandbox limits, reply modes) stays in
   `<state-dir>/settings.json`.

6. Edit `args` to use absolute paths and one sandbox mode (run `mikan --help` for the flag
   reference):

   ```js
   args: "--state-dir=/srv/mikan/state --sandbox=image:ghcr.io/geminixiang/mikan-sandbox:latest /srv/mikan/workspace",
   ```

   The working-directory argument is optional; without it mikan uses `<state-dir>/workspace` and
   creates it on first start.

7. Start and persist the process:

   ```bash
   pm2 start ecosystem.config.cjs
   pm2 save
   pm2 startup
   ```

8. Run the command printed by `pm2 startup` to enable boot startup.

</Steps>

Relative workspace paths are resolved from PM2's current working directory. Absolute paths avoid silently opening a different workspace after service migration or reboot.

## Upgrade

```bash
npm i -g @geminixiang/mikan
pm2 reload mikan
```

If the new version has pending [State migrations](#state-migrations), run them before reloading.

After editing `~/.mikan/mikan.env`, reload through the ecosystem file so the environment is
re-read:

```bash
pm2 reload ecosystem.config.cjs
```

<Aside type="note" title="Graceful reload">
  The included PM2 configuration waits up to six minutes after the stop signal before SIGKILL. mikan
  stops accepting new messages immediately, lets in-flight runs finish for up to five minutes, then
  aborts the rest and posts a restart notice in those conversations, then gives observability
  exporters up to five seconds to flush and shut down. `pm2 reload` in fork mode is sequential, so
  the drain is also a window with no process connected to the platforms; deploy off-peak.
</Aside>

### State migrations

A release that changes the format of persisted files ships a numbered migration. The daemon refuses
to start while one is pending and prints the exact `mikan migrate` command to run; it never converts
files on its own. `<state-dir>/migrations.json` records which migrations have been applied.

Check for pending migrations after installing a new version. `--dry-run` only reads, so it is safe
while the daemon runs. Pass the same `--sandbox`, `--state-dir`, and workspace the daemon uses:

```bash
mikan migrate --sandbox=image:mikan-sandbox:latest --workspace=/srv/mikan/workspace --dry-run
```

If it prints `No pending migrations.`, reload as above. Otherwise stop the daemon, apply them, and
start it again:

```bash
pm2 stop mikan
mikan migrate --sandbox=image:mikan-sandbox:latest --workspace=/srv/mikan/workspace
pm2 start mikan
```

A migration stops, without being recorded, when it cannot decide safely: for example, a directory
whose name fits several enabled platforms (bare digits with both Telegram and Discord running), or a
conversation present under both an old and a new name. The error names each path and the fix. Name
an ambiguous owner with `--owner <conversationId>=<platform>` (repeatable) and run again; the
migrations that already succeeded stay applied.

### Upgrading from 0.5.3

1.0.0 migrates a 0.5.3 install directly; prerelease-only formats are not supported. `mikan migrate`:

- renames conversation directories and their vaults from raw conversation ids to office keys;
- renames `host` per-user vaults and the `container:*` vault to hashed identity keys;
- moves each conversation's `settings.json` into `<state-dir>/conversations/<office-key>/`;
- converts v3 session files to the current format, keeping each original as `*.v3.bak`;
- moves `<workspace>/events/*.json` into each conversation's host-only event store;
- removes the 0.5.3 sandbox containers, which are recreated from the current image on the next
  message, with an empty `/root`;
- copies `~/.pi/agent/models.json` (or `$PI_CODING_AGENT_DIR/models.json`) to `~/.mikan/models.json`
  when mikan does not have one yet.

Provider API keys come from `models.json` or environment variables. Keys that 0.5.3 read from
`~/.pi/mikan/auth.json` are not migrated; set them in `~/.mikan/mikan.env` before starting.

<Aside type="caution" title="Back up the state directory first">
  Migrations rename directories under both the workspace and the state directory. Take a copy of
  `<state-dir>` and the workspace before migrating.
</Aside>

## Health endpoint

The portal server exists only when `LINK_PORT` is set, or when `LINK_URL` causes the default port `8181` to be used:

```bash
curl http://127.0.0.1:8181/health
# {"ok":true}
```

`/health` is a liveness check for the HTTP process only. It does not verify platform connections, Docker, sandbox provisioning, LLM providers, or event delivery, so do not use it as the only readiness signal.

See the [maintained PM2 ecosystem file on GitHub](https://github.com/geminixiang/mikan/blob/main/deploy/pm2/ecosystem.config.cjs) and [Sandbox modes](/sandbox/) for mode-specific requirements.
