## コマンド早見表

| コマンド                                             | 用途と scope                                                                                                                     |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `/login` / `/pi-login`                               | 15 分間有効な login/vault link を開きます。DM のみ。                                                                             |
| `session` / `/session` / `/pi-session`               | 現在の session viewer を開きます。DM のみ。                                                                                      |
| `/new` / `/pi-new`                                   | 現在の session をリセットします。DM のみ。                                                                                       |
| `/model` / `/pi-model [provider/model[:thinking]]`   | 現在の conversation model を表示または切り替えます。Thinking levels：`off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。 |
| `/auto-reply` / `/pi-auto-reply on\|off\|status`     | 現在の group/channel の auto-reply を制御します。                                                                                |
| `stop` / `/stop`                                     | 一致する実行中の run を停止します。Slack では thread-local routing を正確に保つため、テキスト形式を優先してください。            |
| `/admin` / `/pi-admin`                               | 30 分間有効な admin portal を開きます。                                                                                          |
| `/extensions` / `/pi-extensions`                     | global と conversation extensions、versions、提供される skills を一覧表示します。                                                |
| `/sandbox` / `/pi-sandbox`                           | 現在の sandbox の制限と、この office の door policy・workspace layout を表示します。                                             |
| `/pi-sandbox boost`                                  | managed sandbox runtime が停止するまで、設定された boost limits を適用します。                                                   |
| `/pi-sandbox door`                                   | office の実効 door policy と layout を、指定可能な値とあわせて表示します。                                                       |
| `/pi-sandbox door <default\|isolated\|shared\|full>` | この office の door policy を設定します。下の [Office door policy](#office-door-policy) を参照してください。                     |

`/pi-sandbox` は managed sandbox runtime にのみ適用されます。`host` または `container:<name>` モードでは、このコマンドには `image:*` または `gondolin:*` が必要である旨を返します。

### Office door policy

`/pi-sandbox door` は conversation 自身の door policy override を書き込みます。同じ設定は admin portal からも、office 単位でもグローバル既定値としても指定できます。

| 単語       | 効果                                                                                 |
| ---------- | ------------------------------------------------------------------------------------ |
| `default`  | override を解除し、グローバルな `sandbox.workspace` 設定に従います。                 |
| `isolated` | この office 自身の directory だけを mount します。                                   |
| `shared`   | Trusted door: office に加えて workspace レベルの `MEMORY.md`、`skills/`、`events/`。 |
| `full`     | Trusted door: workspace 全体を mount します。                                        |

変更は次のメッセージから有効になり、その時点で sandbox runtime が新しい mount で再構築されます。既存の container の内容は保持されます。conversation が実行中の場合、切り替えは拒否されます。背後にある `sandbox.workspace` fields は [設定](/ja/configuration/) を参照してください。

<Aside type="note" title="プラットフォームへのコマンド登録">
  Native slash commands はプラットフォームにも登録する必要があります。コマンド一覧は
  `src/commands/manifest.ts` にあり、Discord の application commands と Telegram の command menu は
  起動時にそこから導出されます。Slack の routing は manifest の `/pi-*` 名を認識します。Discord は
  100 文字を超える option description を拒否するため、manifest の引数 description は command tests
  で長さが検証されます。Slack の App manifest（`/pi-login`、`/pi-session`、`/pi-new`、
  `/pi-model`、`/pi-auto-reply`、`/pi-sandbox`、`/pi-extensions`、`/pi-admin`）は引き続き Slack App
  設定で手動更新が必要です。
</Aside>

## 共有 vault コマンド

すべての vault commands は DM 専用です：

| コマンド                      | 効果                                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------------- |
| `/login shared list`          | 共有 login profiles を一覧表示します。                                                |
| `/login shared create <name>` | 共有 profile を作成する login link を開きます。                                       |
| `/login shared update <name>` | 共有 profile を更新する login link を開きます。                                       |
| `/login shared delete <name>` | 共有 profile を削除します。                                                           |
| `/login copy <name>`          | 共有 profile を現在の conversation vault にコピーします。一致する値は上書きされます。 |

共有 profiles は operator が管理する credentials です。`sandbox.defaultSharedVault` による自動継承は、対象となる membership-trust image/Cloudflare conversations に限定されます。GitHub のような open-trigger surfaces は継承しません。

## Web portals

admin、login/vault、session portals は同じ HTTP server を使います。本番環境では public base URL を設定します：

<Steps>

1. 外部から到達可能な URL を設定します：

   ```bash
   export LINK_URL="https://mikan.example.com"
   ```

2. 必要に応じて listen port を選択します。`LINK_URL` が存在する場合、既定値は `8181` です：

   ```bash
   export LINK_PORT=8181
   ```

3. ローカルのみのテストでは `LINK_PORT` だけを設定します。mikan は `127.0.0.1` に bind し、
   `http://localhost:<port>` の link を返します。

</Steps>

Capability URLs は bearer secrets です。共有 channels、logs、issue trackers に貼り付けないでください。Login links は 15 分後に期限切れとなり、credentials の書き込み時に消費されます。admin links は 30 分、session links は 24 時間有効です。process restart ですべての未使用 links が無効になります。

route ごとの権限は [Portal 認証と capability モデル](/ja/portal-auth-model/) を参照してください。
