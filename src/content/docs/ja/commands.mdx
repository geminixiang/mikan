## コマンド早見表

| コマンド                                           | 用途と scope                                                                                                                        |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `/login` / `/pi-login`                             | 15 分間有効な login/vault link を開きます。DM のみ。                                                                                |
| `session` / `/session` / `/pi-session`             | 現在の session viewer を開きます。DM のみ。                                                                                         |
| `/new` / `/pi-new`                                 | 現在の session をリセットします。DM のみ。                                                                                          |
| `/model` / `/pi-model [provider/model[:thinking]]` | 現在の conversation model を表示または切り替えます。Thinking levels：`off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。    |
| `stop` / `/stop`                                   | 一致する実行中の run を停止します。Slack では thread-local routing を正確に保つため、テキスト形式を優先してください。               |
| `/pi-auto-reply <on\|off>`                         | 現在の Slack channel で mention なしの応答を有効または無効にします。                                                                |
| `/admin` / `/pi-admin`                             | 30 分間有効な admin portal を開きます。                                                                                             |
| `/sandbox` / `/pi-sandbox`                         | 現在の sandbox の制限と、この office の visibility を表示します。                                                                   |
| `/pi-sandbox boost`                                | managed sandbox runtime が停止するまで、設定された boost limits を適用します。                                                      |
| `/pi-sandbox visibility`                           | office の実効 visibility とその由来を表示します。                                                                                   |
| `/pi-sandbox visibility <private\|default>`        | この public channel を private office に狭めるか、その override を解除します。下の [Office visibility](#office-visibility) を参照。 |

### Office visibility

visibility は Slack の conversation type に従います（ADR 0008）。public channel は public office で、他のすべての office が `/workspace/public/` で読み取り専用に参照でき、共有の `MEMORY.md` と `skills/` に書き込めます。private channel、DM、group DM、外部共有 channel は private office で、自分自身にだけ見えます。`/pi-sandbox visibility` は admin 向けの escape hatch で、モデルが許す唯一の調整——public channel を private として扱う——だけを行います。admin portal にも office ごとに同じスイッチがあります。

| 単語      | 効果                                                                                                               |
| --------- | ------------------------------------------------------------------------------------------------------------------ |
| `default` | override を解除し、Slack の conversation type に従います。                                                         |
| `private` | この public channel を private として扱います。DM や private channel は既に private なので追加の効果はありません。 |

変更は次のメッセージから有効になり、その時点で sandbox runtime が新しい mount で再構築されます。既存の container の内容は保持されます。conversation が実行中の場合、切り替えは拒否されます。背後にある `office.visibility` field は [設定](/ja/configuration/) を参照してください。

<Aside type="note" title="プラットフォームへのコマンド登録">
  Native slash commands はプラットフォームにも登録する必要があります。コマンド一覧は
  `src/adapters/commands/manifest.ts` にあり、Discord の application commands と Telegram の command
  menu は 起動時にそこから導出されます。Slack の routing は manifest の `/pi-*`
  名を認識します。Discord は 100 文字を超える option description を拒否するため、manifest の引数
  description は command tests で長さが検証されます。Slack の `/pi-login`、`/pi-session`、
  `/pi-new`、`/pi-model`、`/pi-sandbox`、`/pi-auto-reply`、`/pi-admin` は Slack App manifest
  にも登録する必要があります。
</Aside>

## 共有 vault コマンド

すべての vault commands は DM 専用です：

| コマンド                      | 効果                                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------------- |
| `/login shared list`          | 共有 login profiles を一覧表示します。                                                |
| `/login shared create <name>` | 共有 profile を作成する login link を開きます。                                       |
| `/login shared update <name>` | 共有 profile を更新する login link を開きます。                                       |
| `/login shared delete <name>` | 共有 profile を削除します。                                                           |
| `/login copy <name>`          | 共有 profile を現在の conversation vault にコピーします。一致する値は上書きされます。 |

共有 profiles は operator が管理する credentials で、明示的な `/login copy <name>` でのみ適用されます。廃止された `sandbox.defaultSharedVault` が新しい conversation にコピーすることはもうありません。

## Web portals

admin、login/vault、session portals は同じ HTTP server を使います。本番環境では public base URL を設定します：

<Steps>

1. 外部から到達可能な URL を設定します：

   ```bash
   export LINK_URL="https://mikan.example.com"
   ```

2. 必要に応じて listen port を選択します。`LINK_URL` が存在する場合、既定値は `8181` です：

   ```bash
   export LINK_PORT=8181
   ```

3. ローカルのみのテストでは `LINK_PORT` だけを設定します。mikan は `127.0.0.1` に bind し、
   `http://localhost:<port>` の link を返します。

</Steps>

Capability URLs は bearer secrets です。共有 channels、logs、issue trackers に貼り付けないでください。Login links は 15 分後に期限切れとなり、credentials の書き込み時に消費されます。admin links は 30 分、session links は 24 時間有効です。process restart ですべての未使用 links が無効になります。

route ごとの権限は [Portal 認証と capability モデル](/ja/portal-auth-model/) を参照してください。
