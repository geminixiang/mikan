## 前提条件

- Node.js `>=24.15.0`
- 少なくとも 1 組の完全な Slack、Telegram、Discord、または GitHub credentials
- 永続的な state directory（既定は `~/.mikan`）。working directory の既定値は `<state-dir>/workspace`
- `image:*` または `container:*` 使用時に PM2 user が利用できる Docker

公開されている `mikan-sandbox` image は tool runtime であり、standalone mikan server image ではありません。PM2 は host 上で `mikan` を実行し、image mode は host Docker daemon を通じて containers を作成、管理します。

## PM2 デプロイ

<Steps>

1. mikan と PM2 をインストールします：

   ```bash
   npm i -g @geminixiang/mikan pm2
   ```

2. service が使用する正確な state directory にグローバル設定ファイルを作成します：

   ```bash
   mkdir -p /srv/mikan/workspace
   mikan onboard --state-dir=/srv/mikan/state
   ```

   `/srv/mikan/state/settings.json` を確認してください。directory は PM2 process user が所有し、
   world-writable でない必要があります。`chmod 0700 /srv/mikan/state` を推奨します。

3. secrets file を作成します。すべての platform tokens、provider keys、その他の secrets は
   `~/.mikan/mikan.env`（mode `0600`、いかなる repo tree の外側）に置き、ecosystem file が起動時に
   読み込みます。secrets を ecosystem file や PM2 自身の環境に置かないでください：

   ```bash
   curl -o ~/.mikan/mikan.env https://raw.githubusercontent.com/geminixiang/mikan/main/deploy/pm2/mikan.env.example
   chmod 600 ~/.mikan/mikan.env
   ```

   少なくとも 1 組の完全な platform credential set と 1 つの LLM provider key を記入します。完全な
   注釈付きインベントリと現在設定されている内容を確認するには `mikan env` を実行します。

4. managed sandbox image を pull します：

   ```bash
   docker pull ghcr.io/geminixiang/mikan-sandbox:latest
   ```

   選択した mode が `image:*` の場合、長時間稼働する container を別途起動しないでください。既存の
   container が必要なのは `container:<name>` mode だけです。

5. ecosystem file をダウンロードします：

   ```bash
   curl -O https://raw.githubusercontent.com/geminixiang/mikan/main/deploy/pm2/ecosystem.config.cjs
   ```

   ecosystem file は supervision 専用です：process 名、restart policy、graceful-shutdown timeout、
   および `mikan.env` の loader です。挙動（model、sandbox limits、reply modes）は
   `<state-dir>/settings.json` に残ります。

6. `args` を編集し、絶対 paths と 1 つの sandbox mode を指定します（flag の一覧は `mikan --help`
   を実行してください）：

   ```js
   args: "--state-dir=/srv/mikan/state --sandbox=image:ghcr.io/geminixiang/mikan-sandbox:latest /srv/mikan/workspace",
   ```

   working-directory 引数は任意です。指定しない場合、mikan は `<state-dir>/workspace` を使用し、
   初回起動時に作成します。

7. process を起動し、永続化します：

   ```bash
   pm2 start ecosystem.config.cjs
   pm2 save
   pm2 startup
   ```

8. `pm2 startup` が出力したコマンドを実行し、boot 時の自動起動を有効にします。

</Steps>

相対 workspace paths は PM2 の current working directory から解決されます。絶対 paths を使うと、service の移行や reboot 後に別の workspace を暗黙に開くことを防げます。

## アップグレード

```bash
npm i -g @geminixiang/mikan
pm2 reload mikan
```

新しいバージョンに未適用の [State マイグレーション](#state-マイグレーション) がある場合は、reload の前に実行してください。

`~/.mikan/mikan.env` を編集した後は、環境が再読み込みされるように ecosystem file 経由で reload
します：

```bash
pm2 reload ecosystem.config.cjs
```

<Aside type="note" title="Graceful reload">
  同梱の PM2 設定は停止シグナル後、SIGKILL まで最大 6 分待機します。mikan は新しいメッセージの
  受付を即座に止め、実行中の runs を最大 5 分完了させ、残りを中止してその会話に再起動の通知を
  投稿し、observability exporters の flush と shutdown を最大 5 秒待ちます。fork モードの `pm2
  reload` は旧プロセス終了後に 新プロセスを起動するため、drain
  中はどのプロセスもプラットフォームに接続していません。 オフピークにデプロイしてください。
</Aside>

### State マイグレーション

永続化ファイルの形式を変えるリリースには、番号付きのマイグレーションが含まれます。未適用のマイグレーションがある間、daemon は起動を拒否し、実行すべき `mikan migrate` コマンドをそのまま表示します。daemon が自分でファイルを変換することはありません。適用済みのマイグレーションは `<state-dir>/migrations.json` に記録されます。

新しいバージョンをインストールしたら、未適用のマイグレーションを確認します。`--dry-run` は読み取りだけなので、daemon の実行中でも安全です。daemon と同じ `--sandbox`、`--state-dir`、workspace を指定します:

```bash
mikan migrate --sandbox=image:mikan-sandbox:latest --workspace=/srv/mikan/workspace --dry-run
```

`No pending migrations.` と表示されたら、上の手順で reload します。そうでなければ daemon を停止し、適用してから再起動します:

```bash
pm2 stop mikan
mikan migrate --sandbox=image:mikan-sandbox:latest --workspace=/srv/mikan/workspace
pm2 start mikan
```

安全に判断できない場合、マイグレーションは記録されずに停止します。たとえば、名前が複数の有効なプラットフォームに当てはまる directory（Telegram と Discord を両方動かしているときの数字だけの id）や、同じ会話が古い名前と新しい名前の両方に存在する場合です。エラーには各パスと対処方法が表示されます。曖昧な所有者は `--owner <conversationId>=<platform>`（繰り返し指定可）で指定して再実行してください。すでに成功したマイグレーションは適用済みのまま残ります。

### 0.5.3 からのアップグレード

1.0.0 は 0.5.3 のインストールを直接マイグレーションします。プレリリースにしか存在しなかった形式はサポート対象外です。`mikan migrate` は次を行います:

- conversation directory とその vault を、生の conversation id から office key へ rename する
- `host` の per-user vault と `container:*` の vault を、hash された identity key へ rename する
- 各会話の `settings.json` を `<state-dir>/conversations/<office-key>/` へ移動する
- 各会話の session file をその `sessions.db` に取り込み、元のファイルを `<state-dir>/conversations/<office-key>/sessions-v3/` に残す
- `<workspace>/events/*.json` を各会話の host 専用 event store へ移動する
- 0.5.3 の sandbox container を削除する。次のメッセージで現在のイメージから空の `/root` で再作成される
- mikan に `~/.mikan/models.json` がまだなければ、`~/.pi/agent/models.json`（または `$PI_CODING_AGENT_DIR/models.json`）をコピーする

Provider の API key は `models.json` か環境変数から読まれます。0.5.3 が `~/.pi/mikan/auth.json` から読んでいた key は移行されないため、起動前に `~/.mikan/mikan.env` に設定してください。

<Aside type="caution" title="先に state directory をバックアップする">
  マイグレーションは workspace と state directory の両方で directory を rename します。実行前に `<state-dir>` と workspace のコピーを取ってください。
</Aside>

## Health endpoint

portal server は `LINK_PORT` が設定されている場合、または `LINK_URL` によって既定 port `8181` が使われる場合にのみ存在します：

```bash
curl http://127.0.0.1:8181/health
# {"ok":true}
```

`/health` は HTTP process の liveness check にすぎません。platform connections、Docker、sandbox provisioning、LLM providers、event delivery は検証しないため、唯一の readiness signal として使用しないでください。

mode 固有の要件は [GitHub で保守されている PM2 ecosystem file](https://github.com/geminixiang/mikan/blob/main/deploy/pm2/ecosystem.config.cjs) と [Sandbox modes](/ja/sandbox/) を参照してください。
