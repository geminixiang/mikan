このガイドでは、約 15 分でボットがメッセージに返信するところまで進めます。token が 1 つで済む Telegram を使います。Node.js 24.15 以上と Docker が必要です。最後に、他のプラットフォームや PM2 での常駐実行へのリンクを示します。

## 前提条件

- Node.js `>=24.15.0`
- Anthropic API key（または対応する他 provider の key）
- Telegram アカウント

<Steps>

1. mikan をインストールします：

   ```bash
   npm i -g @geminixiang/mikan
   ```

2. 対話式セットアップを実行します：

   ```bash
   mikan onboard
   ```

   3 つの質問——チャットプラットフォーム（とその token）、LLM provider（とその API key）、sandbox image——から `~/.mikan/settings.json`、`~/.mikan/mikan.env`（0600）、`~/.mikan/ecosystem.config.cjs` が生成されます。推奨の image を選んでください。カスタム OpenAI 互換エンドポイント（vLLM、proxy）を選ぶと `~/.mikan/models.json` も書き出されます。非対話の stdin では設定テンプレートのみ書き出します。全フィールドは[設定](/ja/configuration/)を参照してください。

   key は環境変数（`<PROVIDER>_API_KEY`、例：`ANTHROPIC_API_KEY`）で直接渡すこともできます。env ファイルはその永続的な置き場所で、pm2 テンプレートが読み込みます。

   Onboarding は office policy を一切書き込みません。visibility は platform の conversation type に従います。Telegram のプライベートチャットは private office で、Docker sandbox は各 office のファイルをその office だけのものに保ちます。

3. Telegram ボットを作成します。[@BotFather](https://t.me/BotFather) にメッセージを送り、`/newbot` を送信してプロンプトに従い、返された token をコピーします：

   ```bash
   export TELEGRAM_BOT_TOKEN="123456:ABC-..."
   ```

4. sandbox image を pull し、mikan をフォアグラウンドで起動します：

   ```bash
   docker pull ghcr.io/geminixiang/mikan-sandbox:latest
   mikan --sandbox=image:ghcr.io/geminixiang/mikan-sandbox:latest
   ```

   image は約 900 MB なので、初回の pull には数分かかります。working directory は既定で `~/.mikan/workspace` になり、自動的に作成されます。別の場所を使うにはフラグの後にパスを渡します。

   その workspace の中で、各会話は自分の **office** を持ちます。これは、その会話のメモリー、添付ファイル、セッションログ、skills、作業領域を保持するディレクトリです。office ディレクトリは生のチャット id ではなく office key（`v1-telegram-…`）で命名されるため、どの office がどの会話のものかを確認するには `mikan office list` を使います。

   起動に失敗した場合は `mikan env` を実行してください。mikan が読み取るすべての変数を、プラットフォームと機能ごとにグループ化し、それぞれの現在の状態とともに表示します。プラットフォームの token が欠けていると、mikan は設定すべき変数名を示すメッセージを出して終了します。`mikan --help` はすべてのフラグを一覧表示します。

5. Telegram でボットとのプライベートチャットを開き、メッセージを送信します。プライベートメッセージは agent を直接トリガーするため、数秒以内に返信が届くはずです。

</Steps>

<Aside type="tip" title="常駐させる">
  ターミナルを閉じても mikan を動かし続けるには、[デプロイ](/ja/deployment/)を参照してください。
  `pm2 start ~/.mikan/ecosystem.config.cjs` は同じコマンドを PM2 の下で実行します。
</Aside>

## 次のステップ

- **Telegram の代わりに Slack、Discord、GitHub を使う** — 各プラットフォームには固有の認証情報が必要です。[Slack 最小セットアップガイド](/ja/slack-bot-minimal-guide/)、[Discord アダプター](/ja/platform-adapters/discord/)、[GitHub アダプター](/ja/platform-adapters/github/)を参照してください。
- **本番利用での分離** — ビルド済み sandbox image を pull し、`--sandbox=image:...` で起動します。[Image sandbox](/ja/sandbox/image/) を参照してください。
- **agent の tools 用の認証情報** — DM で `/login` を入力すると、API key や OAuth 認証情報を保存する vault portal が開きます。[Vault](/ja/sandbox/vault/) を参照してください。
- **サービスとして実行する** — PM2 のセットアップ、アップグレード、ヘルスチェックは[デプロイ](/ja/deployment/)を参照してください。
- **すべての設定とコマンド** — [設定](/ja/configuration/)と[チャットコマンド](/ja/commands/)。
