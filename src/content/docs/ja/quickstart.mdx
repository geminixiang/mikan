このガイドでは、約 15 分でボットがメッセージに返信するところまで進めます。token が 1 つで済む Telegram と、Docker の設定が不要な `host` sandbox を使います。最後に、他のプラットフォームや本格的な分離手段へのリンクを示します。

## 前提条件

- Node.js `>=22.19.0`
- Anthropic API key（または対応する他 provider の key）
- Telegram アカウント

<Steps>

1. mikan をインストールします：

   ```bash
   npm i -g @geminixiang/mikan
   ```

2. 対話式セットアップを実行します：

   ```bash
   mikan onboard
   ```

   3 つの質問——チャットプラットフォーム（とその token）、LLM provider（とその API key）、sandbox モード——から `~/.mikan/settings.json` と `~/.mikan/mikan.env`（0600）が生成されます。カスタム OpenAI 互換エンドポイント（vLLM、proxy）を選ぶと `~/.mikan/models.json` も書き出されます。非対話の stdin では設定テンプレートのみ書き出します。全フィールドは[設定](/ja/configuration/)を参照してください。

   key は環境変数（`<PROVIDER>_API_KEY`、例：`ANTHROPIC_API_KEY`）で直接渡すこともできます。env ファイルはその永続的な置き場所で、pm2 テンプレートが読み込みます。

   Onboarding は workspace policy を固定せず、platform visibility に従わせます。Telegram の private chat は fail closed で `isolated` になり、これを強制できるのは管理型 Docker sandbox だけです。このガイドは `host` を使うため、次の内容を `~/.mikan/settings.json` にマージして workspace を trusted としてマークしてください：

   ```json
   {
     "sandbox": {
       "workspace": { "doorPolicy": "trusted", "layout": "shared-support" }
     }
   }
   ```

   代わりに管理型の [image sandbox](/ja/sandbox/image/)（`--sandbox=image:…`）から始める場合は、この編集は不要です。platform-derived isolated projection をそのまま強制できます。

3. Telegram ボットを作成します。[@BotFather](https://t.me/BotFather) にメッセージを送り、`/newbot` を送信してプロンプトに従い、返された token をコピーします：

   ```bash
   export TELEGRAM_BOT_TOKEN="123456:ABC-..."
   ```

4. mikan を起動します：

   ```bash
   mikan --sandbox=host
   ```

   working directory は既定で `~/.mikan/workspace` になり、自動的に作成されます。別の場所を使うにはパスを渡します（`mikan --sandbox=host ~/mikan-workspace`）。

   その workspace の中で、各会話は自分の **office** を持ちます。これは、その会話のメモリー、添付ファイル、セッションログ、skills、作業領域を保持するディレクトリです。office ディレクトリは生のチャット id ではなく office key（`v1-telegram-…`）で命名されるため、どの office がどの会話のものかを確認するには `mikan office list` を使います。

   起動に失敗した場合は `mikan env` を実行してください。mikan が読み取るすべての変数を、プラットフォームと機能ごとにグループ化し、それぞれの現在の状態とともに表示します。プラットフォームの token が欠けていると、mikan は設定すべき変数名を示すメッセージを出して終了します。`mikan --help` はすべてのフラグを一覧表示します。

5. Telegram でボットとのプライベートチャットを開き、メッセージを送信します。プライベートメッセージは agent を直接トリガーするため、数秒以内に返信が届くはずです。

</Steps>

<Aside type="caution" title="host sandbox はあなたのマシン上で実行されます">
  `host` mode では、agent
  のコマンドはあなたの権限であなたのマシン上で直接実行されます。信頼できるマシンで
  最初に試すのに適した mode です。他の人がボットと会話できるようにする前に、会話ごとに分離された
  Docker コンテナを提供する管理型の [image sandbox](/ja/sandbox/image/) に切り替え、trusted な door
  policy の上書きを削除して platform-derived workspace policy が再び適用されるようにしてください。
</Aside>

## 次のステップ

- **Telegram の代わりに Slack、Discord、GitHub を使う** — 各プラットフォームには固有の認証情報が必要です。[Slack 最小セットアップガイド](/ja/slack-bot-minimal-guide/)、[Discord アダプター](/ja/platform-adapters/discord/)、[GitHub アダプター](/ja/platform-adapters/github/)を参照してください。
- **本番利用での分離** — ビルド済み sandbox image を pull し、`--sandbox=image:...` で起動します。[Image sandbox](/ja/sandbox/image/) を参照してください。
- **agent の tools 用の認証情報** — DM で `/login` を入力すると、API key や OAuth 認証情報を保存する vault portal が開きます。[Vault](/ja/sandbox/vault/) を参照してください。
- **サービスとして実行する** — PM2 のセットアップ、アップグレード、ヘルスチェックは[デプロイ](/ja/deployment/)を参照してください。
- **すべての設定とコマンド** — [設定](/ja/configuration/)と[チャットコマンド](/ja/commands/)。
