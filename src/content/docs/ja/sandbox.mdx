mikan の sandbox は `oci` の 1 種類です。mikan は conversation office ごとに container を 1 つ作成して管理し、その office の workspace mount、vault の env とファイル、リソース制限を与えます。`--sandbox=oci` はインストールされている mikan のバージョン用に公開されたイメージを、`--sandbox=oci:<image>` は別のイメージを使います。`--sandbox` を指定しない場合は `oci` になります。host でコンテナエンジン（nerdctl、Podman、Docker のいずれか）が使える必要があります。

1 つの conversation は vault を 1 つ、container を 1 つ持ちます。vault の名前は office key です。office key は、workspace 配下でその conversation の directory も命名する、バージョン付きの `v1-<platform>-<readable-id>-<hash>` セグメントです。[Conversation office](#conversation-office) を参照してください。

<Aside type="note" title="sandbox の位置づけ">
  `oci:*` は 1 台の VM を共有するチーム向けです。office
  ごとにリソース制限、ファイルシステムの隔離、独立した環境を 提供します。E2B や SaaS sandbox
  のような悪意あるテナントを想定した強い隔離ではありません。container は host kernel を共有し、VM
  上の利用者は互いに信頼されています。認証情報が sandbox に入るのは、開発作業（`gh`、
  `gcloud`、`gws`）に必要だからにすぎません。
</Aside>

<Aside type="caution" title="モード名">
  `host`、`container:<name>`、`docker:*` は sandbox のモードではなく、mikan は起動時に拒否します。
  `oci` または `oci:<image>` を使ってください。
</Aside>

## Conversation office

各 conversation は workspace root 配下に 1 つの directory — その _office_ — を所有します。この
directory はプラットフォームの生の conversation id ではなく office key で命名されます。sandbox の
mount はこの directory に従うため、runtime の中では office は `/workspace/<office-key>` にあります。

runtime が workspace のどの部分を見るかは、その office の **visibility**（ADR 0008）に従います。visibility は Slack の conversation type から導出されます。public channel は public、private channel・DM・group DM・外部共有 channel・未知の種別は private です。すべての office は同じ mount 形状を持ち、違うのは読み取り専用フラグだけです：

| `/workspace` 配下に mount されるもの            | Public office | Private office |
| ----------------------------------------------- | ------------- | -------------- |
| `<office-key>/` — office 自身                   | 読み書き      | 読み書き       |
| `MEMORY.md`、`skills/` — 共有知識               | 読み書き      | 読み取り専用   |
| `public/<office-key>/` — すべての public office | 読み取り専用  | 読み取り専用   |

workspace root を mount する layout はありません。admin portal で public channel を private に狭められますが、Slack の設定より広げることはできません。フィールドの意味と廃止された door policy 設定は [設定](/ja/configuration/) を参照してください。

<Aside type="caution" title="visibility は追加の sandbox ではありません">
  visibility が決めるのは、どの host directory が runtime に投影されるかです。実行の隔離は
  変わりません。どの office も、visibility にかかわらず自分の container の中で動きます。
</Aside>

### 生 id 配置からのアップグレード

0.5.3 の workspace は生の conversation id で directory を命名しています。`mikan migrate` がそれらを vault、設定、session、event とあわせて office layout へ移動します。[0.5.3 からのアップグレード](/ja/deployment/#053-からのアップグレード)を参照してください。
