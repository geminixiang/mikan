## 対応モード

| モード                                                      | 実行場所                    | Vault env injection | Vault key                        | 備考                                                                                                                       |
| ----------------------------------------------------------- | --------------------------- | ------------------- | -------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `host`                                                      | ホストマシン                | 注入しない          | プラットフォームの user から導出 | ローカル開発専用。明示的な trusted door policy が必要                                                                      |
| `container:<name>`                                          | 既存 Docker container       | 注入                | container 名から導出             | one container one vault。複数人が同じ container を共有すると、その vault も共有します                                      |
| `image:<image>`                                             | mikan 管理の Docker         | 注入                | office key                       | 現在もっとも推奨される隔離モード。`1 conversation = 1 vault = 1 container`                                                 |
| `gondolin:default`                                          | ローカルの Gondolin/QEMU VM | 注入                | office key                       | プレビュー。single-host で、mikan 自身のプロセス内で動作。Node.js >=23.6 と QEMU が必要                                    |
| `firecracker:<vm-id>:<host-path>[:<ssh-user>[:<ssh-port>]]` | Firecracker VM              | 注入                | office key                       | Alpha のかなり初期段階。VM は自分で起動し、workspace は VM 内の `/workspace` に mount する必要があります。現時点では非推奨 |
| `cloudflare:<sandbox-id>`                                   | Cloudflare Worker           | 注入                | office key                       | 構築中。`@cloudflare/sandbox` bridge を自分でデプロイする必要があり、host workspace は同期されません                       |

office key は、workspace 配下でその conversation の directory も命名する、バージョン付きの
`v1-<platform>-<readable-id>-<hash>` セグメントです。[Conversation office](#conversation-office) を
参照してください。

## Conversation office

各 conversation は workspace root 配下に 1 つの directory — その _office_ — を所有します。この
directory はプラットフォームの生の conversation id ではなく office key で命名されます。sandbox の
mount はこの directory に従うため、runtime の中では office は `/workspace/<office-key>` にあります。

runtime が workspace のどの部分を見るかは **door policy** で決まります。これは `sandbox.workspace`
設定で、admin portal からグローバルにも conversation ごとにも設定できます（`/pi-sandbox door` チャット
コマンドは 1 つの conversation について同じことをしますが、`image:*` と `gondolin:*` でのみ有効です）：

| Door policy / layout         | `/workspace` 配下に mount されるもの                             |
| ---------------------------- | ---------------------------------------------------------------- |
| `isolated`（既定）           | `<office-key>/` のみ                                             |
| `trusted` / `shared-support` | `<office-key>/` に加えて共有の `MEMORY.md`、`skills/`、`events/` |
| `trusted` / `full`           | workspace root 全体                                              |

isolated な projection を強制できるのは `image:*` と `gondolin:default` だけです。他のモードは
`managedProjection: false` を報告し、`isolated` が既定であるため、その office について誰かが明示的に
trusted な policy を選ぶまで実行を開始しません。フィールドの意味と旧来の
`sandbox.image.workspaceMount` の変換は [設定](/ja/configuration/) に記載しています。

<Aside type="caution" title="trusted な door は追加の sandbox ではありません">
  Door policy が決めるのは、どの host directory が runtime に投影されるかです。実行の境界では
  ありません。`host` mode はどの policy を選んでも、ファイルシステムやプロセスの隔離なしに host 上で
  直接ツールを実行しますし、`full` layout は runtime にすべての conversation の office を渡します。
</Aside>

### 生 id 配置からのアップグレード

office 配置より前に作成された workspace には、生の conversation id で命名された directory が
含まれます。起動のたびにそれらは移行されます — workspace directory、conversation の vault key、
conversation ごとの host state — そして各移動が journal されるため、中断しても conversation を
失わずに再開できます。

推測せず、意図的に boot を止める状況が 2 つあります：

- **所有者不明の directory。** 複数のプラットフォームが有効な場合、mikan はどれが生 directory の
  所有者かを判定できません。`mikan office claim <conversationId> <platform>` で所有者を指定し
  （daemon は停止した状態で）、次回起動時に移動が実行されます。
- **衝突**、つまり legacy と office key の両方の directory がすでに存在する場合。これらは手作業での
  統合のために報告され、上書きされることはありません。

管理下の container は rename をまたいで生き残ります。bind は実行中の container の snapshot に対して
変換されるため、writable layer は base image から作り直されるのではなく保持されます。

## 機能差分

`image:<image>` <Badge text="推奨" variant="success" /> は現在の主要開発および推奨 sandbox モードです。他のモードはローカル開発、互換、または実験用途として残されており、一部機能は補完されません。

| 機能                                 | `host`       | `container:<name>`  | `image:<image>` | `gondolin:default`    | `firecracker:*`     | `cloudflare:*` |
| ------------------------------------ | ------------ | ------------------- | --------------- | --------------------- | ------------------- | -------------- |
| command 実行                         | ✅           | ✅                  | ✅              | ✅                    | ✅                  | ✅             |
| mikan 管理の runtime lifecycle       | 対象外       | ❌                  | ✅              | ✅ mikan process 所有 | ❌                  | ❌             |
| per-conversation container / runtime | ❌           | ❌                  | ✅              | ✅                    | 自分で管理          | bridge 派生 id |
| per-conversation vault env           | ❌           | ❌                  | ✅              | ✅                    | ✅                  | ✅             |
| vault file 自動投影 / bind mount     | ❌           | ❌                  | ✅              | ✅                    | ❌                  | ❌             |
| workspace 自動マウント               | host         | 自分で mount が必要 | ✅              | ✅                    | 自分で mount が必要 | ❌             |
| 隔離された conversation office       | ❌           | ❌                  | ✅              | ✅                    | ❌                  | ❌             |
| idle auto-stop / recreate            | 対象外       | ❌                  | ✅              | ✅                    | ❌                  | ❌             |
| CPU / memory default limits          | ❌           | ❌                  | ✅              | ✅                    | ❌                  | ❌             |
| `/pi-sandbox boost`                  | ❌           | ❌                  | ✅              | ✅                    | ❌                  | ❌             |
| agent `sandbox` tool 設定 limits     | ❌           | ❌                  | ✅              | ✅                    | ❌                  | ❌             |
| 推奨度                               | ローカル開発 | legacy / 互換       | 主流            | preview               | alpha               | 構築中         |

上の 2 つの ❌ の行は、黙って機能を落とすのではなく拒否します。isolated な projection を強制できない
モードは、policy が求めた以上を mount する代わりに
`Sandbox '<type>' cannot provide an isolated conversation office` を送出します。vault file を mount
できないモードは、認証情報なしで実行する代わりに
`Sandbox type "<type>" does not support vault file mounts` を送出します。ファイルを投影できない
モードでは、vault の認証情報は `env` のみに留めてください。
