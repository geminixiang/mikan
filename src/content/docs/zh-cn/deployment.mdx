## 前提条件

- Node.js `>=24.15.0`
- 至少一套完整的 Slack、Telegram、Discord 或 GitHub 凭证
- 持久 state directory（默认 `~/.mikan`）；工作目录默认为 `<state-dir>/workspace`
- 使用 `image:*` 或 `container:*` 时，PM2 用户可以使用 Docker

发布的 `mikan-sandbox` 镜像是工具运行时，不是独立的 mikan 服务器镜像。PM2 在主机上运行 `mikan`；image 模式通过主机 Docker daemon 创建和管理容器。

## PM2 部署

<Steps>

1. 安装 mikan 和 PM2：

   ```bash
   npm i -g @geminixiang/mikan pm2
   ```

2. 在服务将使用的确切 state directory 中创建全局设置文件：

   ```bash
   mkdir -p /srv/mikan/workspace
   mikan onboard --state-dir=/srv/mikan/state
   ```

   检查 `/srv/mikan/state/settings.json`。该目录必须归 PM2 进程用户所有，且不能全局可写；
   建议执行 `chmod 0700 /srv/mikan/state`。

3. 创建 secrets 文件。所有平台 token、provider key 及其他 secret 都存放在
   `~/.mikan/mikan.env`——权限 `0600`、位于任何 repo 树之外——ecosystem 文件会在启动时加载它。
   切勿把 secret 放进 ecosystem 文件或 PM2 自身的环境中：

   ```bash
   curl -o ~/.mikan/mikan.env https://raw.githubusercontent.com/geminixiang/mikan/main/deploy/pm2/mikan.env.example
   chmod 600 ~/.mikan/mikan.env
   ```

   至少填入一套完整的平台凭证以及一个 LLM provider key。运行 `mikan env`
   可查看完整的带注释清单及当前的设置状态。

4. 拉取管理的沙箱镜像：

   ```bash
   docker pull ghcr.io/geminixiang/mikan-sandbox:latest
   ```

   选择 `image:*` 模式时，不要另外启动长期运行的容器。只有 `container:<name>` 模式才需要预先存在的容器。

5. 下载 ecosystem 文件：

   ```bash
   curl -O https://raw.githubusercontent.com/geminixiang/mikan/main/deploy/pm2/ecosystem.config.cjs
   ```

   ecosystem 文件仅用于进程监管：进程名称、重启策略、优雅关闭超时以及 `mikan.env` 加载器。
   行为（模型、沙箱限制、回复模式）仍保留在 `<state-dir>/settings.json` 中。

6. 编辑 `args`，使用绝对路径和一种沙箱模式（运行 `mikan --help` 查看参数参考）：

   ```js
   args: "--state-dir=/srv/mikan/state --sandbox=image:ghcr.io/geminixiang/mikan-sandbox:latest /srv/mikan/workspace",
   ```

   工作目录参数是可选的；不提供时 mikan 会使用 `<state-dir>/workspace` 并在首次启动时创建它。

7. 启动并持久保存进程：

   ```bash
   pm2 start ecosystem.config.cjs
   pm2 save
   pm2 startup
   ```

8. 运行 `pm2 startup` 输出的命令，启用开机启动。

</Steps>

相对工作区路径从 PM2 的当前工作目录解析。绝对路径可避免服务迁移或重启后无意中打开其他工作区。

## 升级

```bash
npm i -g @geminixiang/mikan
pm2 reload mikan
```

如果新版本有待应用的 [State 迁移](#state-迁移)，请先执行再重新加载。

编辑 `~/.mikan/mikan.env` 之后，请通过 ecosystem 文件重新加载，以便重新读取环境：

```bash
pm2 reload ecosystem.config.cjs
```

<Aside type="note" title="优雅重新加载">
  随附的 PM2 配置会在 SIGTERM 后等待最多 60 秒，再发送 SIGKILL。mikan 会先排空对话运行，停止 events
  watcher，并给 observability exporters
  最多五秒钟完成刷新和关闭。超过进程管理器超时时间的运行仍可能被终止。
</Aside>

### State 迁移

会改变持久化文件格式的版本会附带一个有编号的迁移。只要还有待应用的迁移，daemon 就会拒绝启动，并打印应执行的完整 `mikan migrate` 命令；它不会自行转换任何文件。已应用的迁移记录在 `<state-dir>/migrations.json`。

安装新版本后，先检查有没有待应用的迁移。`--dry-run` 只读取，daemon 运行时也可以安全使用。请传入与 daemon 相同的 `--sandbox`、`--state-dir` 和工作区：

```bash
mikan migrate --sandbox=image:mikan-sandbox:latest --workspace=/srv/mikan/workspace --dry-run
```

如果输出 `No pending migrations.`，按上面的方式重新加载即可。否则先停止 daemon、应用迁移，再重新启动：

```bash
pm2 stop mikan
mikan migrate --sandbox=image:mikan-sandbox:latest --workspace=/srv/mikan/workspace
pm2 start mikan
```

遇到无法安全判断的情况，迁移会停止且不会被记录，例如：目录名同时符合多个已启用平台（Telegram 与 Discord 同时运行时的纯数字 id），或同一对话同时存在新旧两个名称。错误信息会列出每个路径及处理方法。用 `--owner <conversationId>=<platform>`（可重复）指定有歧义目录的所有者后再运行一次；已经成功的迁移会保持已应用。

### 从 0.5.3 升级

1.0.0 可以直接迁移 0.5.3 的安装；仅在预览版中出现过的格式不在支持范围内。`mikan migrate` 会：

- 把对话目录及其 vault 从原始对话 id 重命名为 office key；
- 把 `host` 模式的每用户 vault 和 `container:*` 的 vault 重命名为哈希后的 identity key；
- 把每个对话的 `settings.json` 移到 `<state-dir>/conversations/<office-key>/`；
- 把每个对话的会话文件导入它的 `sessions.db`，原文件保留在 `<state-dir>/conversations/<office-key>/sessions-v3/`；
- 把 `<workspace>/events/*.json` 移到各对话仅主机可见的事件存储；
- 删除 0.5.3 的沙盒容器；下一条消息到来时会用当前镜像重建，`/root` 从空开始；
- 如果 mikan 还没有 `~/.mikan/models.json`，就复制 `~/.pi/agent/models.json`（或 `$PI_CODING_AGENT_DIR/models.json`）。

Provider API key 来自 `models.json` 或环境变量。0.5.3 从 `~/.pi/mikan/auth.json` 读取的 key 不会被迁移；请在启动前设置到 `~/.mikan/mikan.env`。

<Aside type="caution" title="请先备份 state directory">
  迁移会同时重命名工作区和 state directory 下的目录。迁移前请先复制一份 `<state-dir>` 和工作区。
</Aside>

## 健康端点

Portal 服务器仅在设置 `LINK_PORT` 时存在；如果 `LINK_URL` 使默认端口 `8181` 生效，也会存在：

```bash
curl http://127.0.0.1:8181/health
# {"ok":true}
```

`/health` 仅检查 HTTP 进程是否存活。它不会验证平台连接、Docker、沙箱 provision、LLM 提供商或事件投递，因此不要将其用作唯一的就绪信号。

请参阅 [GitHub 上维护的 PM2 ecosystem 文件](https://github.com/geminixiang/mikan/blob/main/deploy/pm2/ecosystem.config.cjs)和[沙箱模式](/zh-cn/sandbox/)了解特定模式的要求。
