mikan 只有一种 sandbox：`oci`。mikan 为每个对话办公室创建并管理一个容器，并提供该办公室的 workspace mount、vault 的环境变量与文件，以及资源限制。`--sandbox=oci` 使用为当前安装的 mikan 版本发布的镜像，`--sandbox=oci:<image>` 使用其他镜像；不带 `--sandbox` 时，mikan 使用 `oci`。主机上必须有可用的容器引擎（nerdctl、Podman 或 Docker）。

一个对话对应一个 vault 和一个容器。vault 以 office key 命名：office key 就是带版本的 `v1-<platform>-<readable-id>-<hash>` 路径段，它同时也命名该对话在 workspace 下的目录。参阅[对话办公室](#对话办公室)。

<Aside type="note" title="sandbox 的定位">
  `oci:*` 面向共用一台 VM 的团队。每个 office 有自己的资源限制、文件系统隔离与独立环境。它不是 E2B
  或 SaaS sandbox 那种对抗恶意租户的强隔离：container 共用宿主机 kernel，VM
  上的人彼此互信。凭证会进入 sandbox，只是因为开发工作（`gh`、`gcloud`、`gws`）需要它们。
</Aside>

<Aside type="caution" title="模式名称">
  `host`、`container:<name>` 和 `docker:*` 不是 sandbox 模式，mikan 会在启动时拒绝它们。请使用 `oci`
  或 `oci:<image>`。
</Aside>

## 对话办公室

每个对话在 workspace 根目录下拥有一个目录——它的**办公室**——按 office key 命名，而不是按平台的原始对话 id。Sandbox mount 跟随该目录，因此在 runtime 内部，办公室位于 `/workspace/<office-key>`。

runtime 能看到 workspace 的哪些部分，跟随该办公室的 **visibility**（ADR 0008），由 Slack 对话类型推导：公开频道是 public；私有频道、DM、群组 DM、外部共享频道与未知类型是 private。每个办公室的挂载形状相同，只差在只读标志：

| 挂载到 `/workspace` 下的内容               | Public office | Private office |
| ------------------------------------------ | ------------- | -------------- |
| `<office-key>/`——办公室本身                | 可读写        | 可读写         |
| `MEMORY.md`、`skills/`——共享知识           | 可读写        | 只读           |
| `public/<office-key>/`——所有 public office | 只读          | 只读           |

没有任何布局会挂载 workspace 根目录。admin portal 可把公开频道收窄为 private；不能放宽超过 Slack 的设置。字段语义与已退役的门禁策略设置见[配置](/zh-cn/configuration/)。

<Aside type="caution" title="visibility 不是额外的 sandbox">
  Visibility 决定哪些主机目录被投影进 runtime。它不改变执行隔离：无论办公室的 visibility
  为何，每个办公室都在自己的容器中运行。
</Aside>

### 从原始 id 布局升级

0.5.3 的工作区以原始对话 id 命名目录。`mikan migrate` 会把它们连同 vault、设置、会话和事件一起移到办公室布局；详见[从 0.5.3 升级](/zh-cn/deployment/#从-053-升级)。
