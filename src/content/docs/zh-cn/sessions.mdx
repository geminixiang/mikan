## 平台会话模型

会话密钥要么是单独的 `conversationId`，要么是限定范围会话的 `conversationId:suffix`。后缀就是平台用来标识话题或回复目标的那个值。

| 平台     | `sessionKey` 规则                                                                                       | 说明                                                          |
| -------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| Slack    | 顶层和 DM：`channelId`；话题（包括 DM 中的）：`channelId:threadTs`                                      | 话题会话是根据近期聊天历史记录初始化的固定文件                |
| Discord  | DM 和共享顶层：`channelId`；话题：`parentChannelId:threadChannelId`；回复：`channelId:repliedMessageId` | guild 话题以其父频道加上话题自身的 id 来寻址                  |
| Telegram | 私聊：`chatId`；共享顶层：`chatId:messageId`；共享回复：`chatId:repliedMessageId`                       | 没有原生话题模型，因此被回复的那条消息就是范围                |
| GitHub   | `GH_<owner>_<repo>_<number>`                                                                            | 一个 issue 或 pull request 是一个扁平会话，含内联 review 话题 |

## 会话密钥与办公室

会话密钥保持为原始平台值——`src/sessions/session-key.ts` 中的语法从不接触 office key。运行时状态按该对话的办公室加其会话密钥寻址，因此两个共用同一原始对话 id 的平台永远无法选中彼此的 runner、队列或 stop 状态。存储路径则跟随办公室：会话文件位于 `<workspace>/<officeKey>/sessions/` 下。

## 会话身份安全

一个会话密钥始终只属于一个对话。平台适配器可以提供带范围的密钥，但对话接收层和运行时会拒绝其对话前缀与传入对话不符的密钥。对话身份和范围后缀也会在影响会话存储之前拒绝路径分隔符、控制字符以及特殊的 `.` / `..` 段。话题会话文件保留其现有名称和持久化行为；会话模块另外会拒绝符号链接会话目标，并确保派生路径始终位于该办公室的 `sessions/` 目录内。

## 话题谱系

限定范围的会话会在其 header 中记录它由哪个顶层会话创建而来，字段为 `parentSession`（路径）和 `parentSessionId`（uuid）。该链接在重置后依然存在：重置一个限定范围会话会重建它的文件，但保留原来的父会话，而不是重新绑定到当前的那个顶层会话。在谱系元数据出现之前写入的会话会被原样保留，不会重建。

## 运维迁移

**迁移前请停止 daemon。** 执行：

```bash
mikan sessions migrate
```

此离线转换会处理旧版 mikan v3 和 Pi 0.84 代 v4 会话文件，并将其改写为当前
Pi 0.85.0 v4 格式。可按需使用 `--state-dir`、`--workspace` 或 `--dry-run`；
`--dry-run` 不会修改文件。原文件会保留为 `*.v3.bak` 或 `*.pi-084.bak`。

## 初始化、轮换、Clean session 与 Dream

新的限定范围会话会从过去 14 天内最多 200 条适用的平台消息初始化。共享频道的顶层会话以每两周一次的星期日边界轮换。轮换采用惰性机制，而不是由 cron 驱动：跨过边界后，第一条符合条件的消息到达时，mikan 才会检查当前会话的时间戳。

`/new` 会立即创建 **Clean session**。双周轮换也只切换活动会话文件。两者都不会总结前一个会话、运行 Dream、等待记忆处理或删除旧 JSONL 文件；现有对话 `MEMORY.md` 仍可独立使用。

**Dream** 是由系统调度的 office maintenance。在台湾时间 02:00–05:00 期间，mikan 会检查每个已登记的 Conversation office；当最新 evidence 已闲置五小时后，Dream 会一次处理该 office 的所有顶层、轮换、线程及事件会话中新累积的 settled entries。成功后会先完整替换对话 `MEMORY.md`，再推进 host-private 的 per-session checkpoint；没有新 evidence 时不会调用模型。

生成的 **Memory anchor** 是精简且可修订的导向信息，不是最终真相。较新的对话 evidence 优先。可变的外部状态必须在回答当次从 Live source 或当前 API 验证；如果来源不可用，mikan 应说明目前无法验证，而不是把 memory 当作当前真相。

<Aside type="tip" title="保留审计记录">
  在私聊中使用 `new` / `/new`
  可立即重新开始。除非手动删除，否则之前的会话文件仍会保留在磁盘上供检查。
</Aside>
