## 平台会话模型

| 平台     | `sessionKey` 规则                                                  | 说明                                           |
| -------- | ------------------------------------------------------------------ | ---------------------------------------------- |
| Slack    | 顶层 / DM：`conversationId`；话题：`conversationId:threadTs`       | 话题会话是根据近期聊天历史记录初始化的固定文件 |
| Discord  | DM：`channelId`；共享顶层：`channelId:messageId`；回复/话题：根 ID | 共享频道中的回复延续根消息会话                 |
| Telegram | 私聊：`chatId`；共享顶层：`chatId:messageId`；回复链：根回复       | 没有原生话题模型；共享会话从回复链推导         |

## 会话身份安全

一个会话密钥始终只属于一个对话。平台适配器可以提供带范围的密钥，但对话接收层和运行时会拒绝其对话前缀与传入对话不符的密钥。对话身份和范围后缀也会在影响会话存储之前拒绝路径分隔符、控制字符以及特殊的 `.` / `..` 段。话题会话文件保留其现有名称和持久化行为；会话模块另外会拒绝符号链接会话目标，并确保派生路径始终位于该对话的 `sessions/` 目录内。

## 文件

<FileTree>

- workspace/
  - **log.jsonl** 平台消息历史记录
  - sessions/
    - **current** 指向活动的顶层会话
    - **\*.jsonl** 结构化框架会话上下文，包括工具结果
    - **scope-derived files** 话题/回复范围的固定会话文件

</FileTree>

## 初始化、轮换、重置与 Session Dream

新的限定范围会话会从过去 14 天内最多 200 条适用的平台消息初始化。共享频道的顶层会话以每两周一次的星期日边界轮换。轮换采用惰性机制，而不是由 cron 驱动：跨过边界后，第一条符合条件的消息到达时，mikan 才会检查当前会话的时间戳。

在 `/new` 重置私聊之前，或双周共享频道轮换切换活动会话之前，mikan 会运行一个隐藏的 **Session Dream**。它会检查旧的结构化记录，只将值得长期保留的决策、偏好、事实和进行中的工作写入该对话的 `MEMORY.md`。Dream 可以读取上下文，但只能修改对话专属的记忆文件；不能修改工作区全局 `MEMORY.md`，也不能将信息提升到其他对话。

```text
旧会话 → Session Dream → conversation/MEMORY.md → 新会话 → 当前消息
```

如果 Session Dream 失败或被阻止，mikan 会保留旧会话，不执行轮换或重置。`/new` 会向用户报告失败；自动轮换则记录错误、在旧会话中处理当前消息，并可能在后续消息到达时重试。成功轮换会更改活动的结构化上下文文件，但不会删除旧的 JSONL 文件。

<Aside type="tip" title="保留审计记录">
  在私聊中使用 `new` / `/new` 时，mikan 会先执行
  Dream，再重置当前会话。除非手动删除，否则之前的会话文件会保留在磁盘上供检查。
</Aside>
