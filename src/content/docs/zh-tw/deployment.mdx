## 先決條件

- Node.js `>=22.19.0`
- 至少一組完整的 Slack、Telegram、Discord 或 GitHub 憑證
- 持久化 state directory（預設為 `~/.mikan`）；working directory 預設為 `<state-dir>/workspace`
- 使用 `image:*` 或 `container:*` 時，PM2 使用者必須可使用 Docker

發布的 `mikan-sandbox` image 是工具 runtime，不是可獨立運作的 mikan server image。PM2 在 host 上執行 `mikan`；image 模式透過 host Docker daemon 建立並管理 containers。

## PM2 部署

<Steps>

1. 安裝 mikan 與 PM2：

   ```bash
   npm i -g @geminixiang/mikan pm2
   ```

2. 在服務實際使用的 state directory 建立全域設定檔：

   ```bash
   mkdir -p /srv/mikan/workspace
   mikan --onboard --state-dir=/srv/mikan/state
   ```

   檢查 `/srv/mikan/state/settings.json`。目錄必須由 PM2 process user 擁有且不得為
   world-writable；建議執行 `chmod 0700 /srv/mikan/state`。

3. 建立 secrets 檔案。所有平台 token、provider key 及其他 secret 都放在
   `~/.mikan/mikan.env`——mode 為 `0600`，且位於任何 repo tree 之外——ecosystem file 會在
   啟動時載入它。絕不要把 secret 放進 ecosystem file 或 PM2 自己的環境：

   ```bash
   curl -o ~/.mikan/mikan.env https://raw.githubusercontent.com/geminixiang/mikan/main/deploy/pm2/mikan.env.example
   chmod 600 ~/.mikan/mikan.env
   ```

   至少填入一組完整的平台憑證，外加一組 LLM provider key。執行 `mikan env` 可查看完整、帶
   註解的清單，以及目前已設定的項目。

4. 拉取受管理 sandbox image：

   ```bash
   docker pull ghcr.io/geminixiang/mikan-sandbox:latest
   ```

   選擇 `image:*` 模式時，不要另外啟動長期運作的 container。只有 `container:<name>`
   模式才需要預先存在的 container。

5. 下載 ecosystem file：

   ```bash
   curl -O https://raw.githubusercontent.com/geminixiang/mikan/main/deploy/pm2/ecosystem.config.cjs
   ```

   這個 ecosystem file 只負責 supervision：process 名稱、restart policy、graceful-shutdown
   timeout，以及 `mikan.env` loader。行為（model、sandbox 限制、reply mode）仍留在
   `<state-dir>/settings.json`。

6. 編輯 `args`，使用絕對路徑及一種 sandbox 模式（執行 `mikan --help` 查看旗標參考）：

   ```js
   args: "--state-dir=/srv/mikan/state --sandbox=image:ghcr.io/geminixiang/mikan-sandbox:latest /srv/mikan/workspace",
   ```

   working-directory 引數是選用的；若省略，mikan 會使用 `<state-dir>/workspace`，並在首次啟動
   時建立它。

7. 啟動並保存程序：

   ```bash
   pm2 start ecosystem.config.cjs
   pm2 save
   pm2 startup
   ```

8. 執行 `pm2 startup` 印出的指令，啟用開機自動啟動。

</Steps>

相對 workspace 路徑會從 PM2 的 current working directory 解析。使用絕對路徑可避免服務移轉或重開機後，無聲地開啟另一個 workspace。

## 升級

```bash
npm i -g @geminixiang/mikan
pm2 reload mikan
```

編輯 `~/.mikan/mikan.env` 之後，請透過 ecosystem file 重新載入，讓環境重新讀取：

```bash
pm2 reload ecosystem.config.cjs
```

<Aside type="note" title="Graceful reload">
  隨附的 PM2 設定會在 SIGTERM 後等待最多 60 秒才送出 SIGKILL。mikan 會先排空 conversation
  runtime、停止 events watcher，並給 Sentry 最多五秒完成 flush。超過 supervisor timeout
  的執行仍可能被終止。
</Aside>

## Health endpoint

只有設定 `LINK_PORT`，或 `LINK_URL` 使系統使用預設 port `8181` 時，portal server 才會存在：

```bash
curl http://127.0.0.1:8181/health
# {"ok":true}
```

`/health` 只檢查 HTTP process 是否存活。它不會驗證平台連線、Docker、sandbox provisioning、LLM providers 或 event delivery，因此不要把它當成唯一的 readiness signal。

請參閱 [GitHub 上維護的 PM2 ecosystem file](https://github.com/geminixiang/mikan/blob/main/deploy/pm2/ecosystem.config.cjs) 與 [Sandbox 模式](/zh-tw/sandbox/) 以瞭解各模式的需求。
