<Aside type="note" title="sandbox 的定位">
  `image:*` 的對象是共用一台 VM 的團隊。每個 office 有自己的資源限制、檔案系統隔離與獨立環境。它不是
  E2B 或 SaaS sandbox 那種對抗惡意租戶的強隔離：container 共用宿主機 kernel，VM
  上的人彼此互信。憑證會進到 sandbox，只是因為開發工作（`gh`、`gcloud`、`gws`）需要它們。
</Aside>

<Aside type="caution" title="模式名稱">
  `docker:*` 不是可用模式；請改用 `container:*` 或 `image:*`。
</Aside>

## 支援模式

| 模式                      | 執行位置              | Vault env injection | Vault key             | 備註                                                                         |
| ------------------------- | --------------------- | ------------------- | --------------------- | ---------------------------------------------------------------------------- |
| `host`                    | 宿主機                | 不注入              | 由平台使用者推導      | 僅供本機開發；無法強制 office visibility                                     |
| `container:<name>`        | 既有 Docker container | 注入                | 由 container 名稱推導 | one container one vault；多人共用同一 container 就共用該 vault               |
| `image:<image>`           | mikan 管理的 Docker   | 注入                | office key            | 目前最推薦的隔離模式；`1 conversation = 1 vault = 1 container`               |
| `cloudflare:<sandbox-id>` | Cloudflare Worker     | 注入                | office key            | 施工中；需自行部署 `@cloudflare/sandbox` bridge，host workspace 不會自動同步 |

office key 是帶版本的 `v1-<platform>-<readable-id>-<hash>` 片段，同時也是該對話在 workspace 底下的目錄名稱。詳見 [Conversation offices](#conversation-offices)。

## Conversation offices

每個對話在 workspace root 底下擁有一個目錄——也就是它的 _office_——目錄名稱使用 office key，而不是平台的原始 conversation id。Sandbox mount 會跟著這個目錄走，因此在 runtime 內部，office 位於 `/workspace/<office-key>`。

runtime 能看到 workspace 的哪些部分，跟隨該 office 的 **visibility**（ADR 0008），由 Slack 對話類型推導：公開頻道是 public；私人頻道、DM、群組 DM、外部共享頻道與未知類型是 private。每個 office 的掛載形狀相同，只差在唯讀旗標：

| 掛進 `/workspace` 的內容                   | Public office | Private office |
| ------------------------------------------ | ------------- | -------------- |
| `<office-key>/`——office 本身               | 可讀寫        | 可讀寫         |
| `MEMORY.md`、`skills/`——共用知識           | 可讀寫        | 唯讀           |
| `public/<office-key>/`——所有 public office | 唯讀          | 唯讀           |

沒有任何佈局會掛載 workspace root。admin portal 或 `/pi-sandbox visibility private` 可把公開頻道縮為 private；不能放寬超過 Slack 的設定。只有 `image:*` 會強制執行 visibility；其他模式回報 `managedProjection: false`，private office 在這些模式下會照常服務並記錄一次警告。欄位語意與已退役的 door policy 設定見 [設定](/zh-tw/configuration/)。

<Aside type="caution" title="visibility 不是額外的 sandbox">
  Visibility 決定哪些宿主機目錄會被投影進 runtime，它不是執行邊界：不論 office 的 visibility
  為何，`host` 模式都是直接在宿主機上執行工具，沒有任何檔案系統或 process 隔離。
</Aside>

### 從 raw-id 佈局升級

在 office 佈局之前建立的 workspace，其目錄是以原始 conversation id 命名。每次開機都會遷移它們——workspace 目錄、conversation vault key、以及各對話的 host state——並為每一次搬移寫下 journal，因此中斷的執行會續做，而不會弄丟某個對話。

有兩種情況會刻意讓開機停下來，而不是用猜的：

- **無主目錄。** 同時啟用多個平台時，mikan 無法判斷某個 raw 目錄屬於哪一個平台。請用 `mikan office claim <conversationId> <platform>`（需先停掉 daemon）指定擁有者，下次啟動就會完成搬移。
- **衝突**，也就是 legacy 目錄與 office key 目錄都已存在。這種情況會回報出來讓人手動合併，絕不會被覆寫。

受管 container 能在改名後存活：它們的 bind 會被轉譯到執行中 container 的 snapshot 上，因此可寫層會被保留，而不是從 base image 重建。

## 能力差異

`image:<image>` <Badge text="推薦" variant="success" /> 是目前主要開發與推薦的 sandbox 模式；其他模式保留為本機開發、相容、或實驗用途，部分能力不會補齊。

| ------------------------------------ | -------- | ------------------ | --------------- | --------------------- | --------------- | -------------- |
| command 執行 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| mikan 管理 runtime lifecycle | 不適用 | ❌ | ✅ | ✅ mikan process 管理 | ❌ | ❌ |
| per-conversation container / runtime | ❌ | ❌ | ✅ | ✅ | 需自行管理 | bridge 衍生 id |
| per-conversation vault env | ❌ | ❌ | ✅ | ✅ | ✅ | ✅ |
| vault file 自動投影 / bind mount | ❌ | ❌ | ✅ | ✅ | ❌ | ❌ |
| workspace 自動掛載 | host | 需自行掛載 | ✅ | ✅ | 需自行掛載 | ❌ |
| 強制執行 office visibility | ❌ | ❌ | ✅ | ✅ | ❌ | ❌ |
| idle auto-stop / recreate | 不適用 | ❌ | ✅ | ✅ | ❌ | ❌ |
| CPU / memory default limits | ❌ | ❌ | ✅ | ✅ | ❌ | ❌ |
| `/pi-sandbox boost` | ❌ | ❌ | ✅ | ✅ | ❌ | ❌ |
| agent `sandbox` tool 設定 limits | ❌ | ❌ | ✅ | ✅ | ❌ | ❌ |
| 推薦程度 | 本機開發 | legacy / 相容 | 主線 | 預覽 | alpha | 施工中 |

上表大多數 ❌ 都是拒絕執行，而不是默默降級。例外是 office visibility：無法強制執行的模式會針對每個 office 記錄一次 `Sandbox '<type>' cannot enforce private office visibility` 並繼續，因為這些模式本身就是受信任部署。無法掛載 vault file 的模式會拋出 `Sandbox type "<type>" does not support vault file mounts`，而不是在缺少該憑證的情況下執行。在無法投影檔案的模式上，請只用 `env` 保存 vault 憑證。
