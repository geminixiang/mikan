## 平台工作階段模型

| 平台     | `sessionKey` 規則                                                                 | 備註                                                          |
| -------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| Slack    | top-level / DM：`conversationId`；thread：`conversationId:threadTs`               | thread sessions 是由近期聊天歷史 bootstrap 的固定檔案         |
| Discord  | DM：`channelId`；shared top-level：`channelId:messageId`；reply/thread：rooted id | shared channels 中的 replies 會延續 root message session      |
| Telegram | private：`chatId`；shared top-level：`chatId:messageId`；reply chain：root reply  | 沒有原生 thread model；shared sessions 會從 reply chains 推斷 |

## 工作階段身分安全

session key 一律只屬於單一對話。平台 adapter 可以提供 scoped key，但對話 intake 與 runtime 會拒絕 conversation prefix 與傳入對話不符的 key。Conversation identity 與 scoped suffix 也會在影響 session 儲存之前，拒絕 path separator、control character，以及特殊的 `.` / `..` segment。Thread session files 維持既有的檔名與持久化行為；sessions 模組還會拒絕 symlink session target，並確保衍生路徑仍留在該對話的 `sessions/` 目錄之內。

## Bootstrap、rotation、重設與 Session Dream

新的 scoped session 最多會以過去 14 天內、符合條件的 200 則平台訊息初始化。Shared channel 的 top-level session 以每兩週一次的星期日邊界輪替。Rotation 採 lazy 機制而非 cron：跨過邊界後，第一則符合條件的訊息抵達時，mikan 才會檢查目前 session 的 timestamp。

在 `/new` 重設 private conversation 前，或 biweekly shared-channel rotation 切換 active session 前，mikan 會執行一個隱藏的 **Session Dream**。它會檢視舊 structured transcript，只將值得長期保留的決策、偏好、事實與進行中工作寫入該 conversation 的 `MEMORY.md`。Dream 可以讀取 context，但只能修改 conversation-specific memory file；不能修改 workspace-global `MEMORY.md`，也不能把資訊提升到其他 conversation。

```text
舊 session → Session Dream → conversation/MEMORY.md → 新 session → 目前訊息
```

若 Session Dream 失敗或被 blocked，mikan 會保留舊 session，不進行 rotation 或 reset。`/new` 會向使用者回報失敗；自動 rotation 則記錄錯誤、在舊 session 處理目前訊息，並可能在之後的訊息再次嘗試。成功 rotation 會變更使用中的 structured context file，但不會刪除舊的 JSONL 檔案。

<Aside type="tip" title="保留可稽核紀錄">
  在 private chat 中使用 `new` / `/new`，會先執行 Dream 再重設目前 session。除非手動移除，先前的
  session files 會留在磁碟上供檢查。
</Aside>
